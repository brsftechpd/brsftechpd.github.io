Инструкции

Обзор инструмента

JSON Editor — Мощный редактор для работы с JSON-данными, специализированный на обработке блоков миграционного учета.

1

Назначение

Инструмент предназначен для:

  • Валидации и форматирования JSON-структур
  • Анализа блоков residenceRegistration и residenceAddress
  • Быстрого исправления статусов постановки на учет
  • Копирования данных в формате Unicode для использования в запросах

Ключевая особенность: Автоматическое определение статусов и подсказки по действиям для миграционных блоков.

2

Основные возможности

  • Подсветка синтаксиса JSON
  • Автоформатирование (pretty-print) при вставке
  • Нумерация строк и изменение размера шрифта
  • Интеллектуальный анализ полей regStatus, unregistrationReasonId
  • Кнопки для исправления статусов (1 или 5) с учётом таймеров
  • Копирование JSON в Unicode-формате (экранирование кириллицы)

Шаблоны JSON блоков

Быстрая вставка заготовок через боковую панель.

1

Боковая панель «Шаблоны JSON блоков»

В левой панели находятся две кнопки:

  • residenceAddress – шаблон блока адреса проживания
  • residenceRegistration – шаблон блока регистрации

При клике соответствующий фрагмент JSON копируется в буфер обмена. Вы можете вставить его в редактор и дополнить своими данными.

Пример шаблона residenceRegistration:
{
  "residenceRegistration": {
    "regStatus": 4,
    "unregistrationReasonId": null,
    "statusMessageCode": null,
    "receiveDate": "2025-11-13T23:03:13.335Z",
    "expirationDate": "2029-09-01T00:00:00",
    "isRkl": false,
    "changeDate": "2025-11-13T01:09:55Z"
  }
}
2

Структура residenceAddress

Содержит поля адреса: addressName, city, street, house, province, point (геокоординаты), а также residenceStatus. Если addressName пуст, панель предупредит об этом.

Работа с JSON

Редактирование, валидация и форматирование.

1

Вставка и валидация

Вставьте JSON в основное поле редактора. Инструмент автоматически:

  • Проверит корректность синтаксиса
  • Отформатирует код с отступами (pretty print)
  • Подсветит ключи, строки, числа и булевы значения разными цветами
  • Покажет статус «Валидный JSON» или «Невалидный JSON» над редактором

Автоматически удаляются лишние поля из residenceRegistration (addressName, flat, city и т.д.), которые могут случайно попасть в этот блок.

2

Настройка отображения

  • Размер шрифта: регулируется слайдером или кнопками «− / 14 / +» в боковой панели. Текущий размер сохраняется в браузере.
  • Нумерация строк: синхронизируется с содержимым редактора, помогает ориентироваться в объёмных JSON.
  • Очистка: кнопка «Очистить» удаляет всё содержимое редактора.

Исправление статусов residenceRegistration

Автоматические подсказки и кнопки для коррекции.

1

Анализ и панели состояния

Если в загруженном JSON найден блок residenceRegistration, над редактором появятся информационные карточки:

  • residenceRegistration – показывает текущий regStatus, причину снятия (при статусе 7) и расшифровку состояния.
  • residenceAddress – информирует, заполнено ли поле addressName.

Описание статуса можно скопировать кликом по карточке.

2

Доступные действия

В зависимости от текущего статуса и причины снятия появляются кнопки:

  • «Исправить на статус 1» – переводит regStatus в 1 (ожидание начала). Доступно при статусе 3 или при статусе 7 с определёнными причинами (1,2,3,6). Для причины 2 (отсутствие геоданных) кнопка становится активной только после таймера (4 дня + полночь).
  • «Исправить на статус 5» – устанавливает статус 5 (требуется повтор). Появляется при статусах 6 или 10.

Если отображается обратный отсчёт – ожидайте окончания таймера, после чего кнопка автоматически станет доступной.

Пример кнопок действий:
⏱️ 2д 03:15:22
3

Расшифровка статусов и причин

Статусы regStatus:

  • 1 – Действий не требуется, пользователь видит кнопку «Начать».
  • 3 – В процессе обработки.
  • 4 – Состоит на учете.
  • 5 – Действий не требуется, пользователь видит кнопку «Повторить».
  • 6 – Отказ в постановке на учет.
  • 7 – Снятие с миграционного учета.
  • 10 – Не распространяются новые правила учета через приложение «Амина».

Причины снятия (unregistrationReasonId) при статусе 7:

  • 1 – Пересечение границы РФ
  • 2 – Отсутствие геоданных
  • 3 – Постановка на учет в другом субъекте РФ
  • 4 – Данные ЗАГС (смерть)
  • 5 – Решение суда (безвестно отсутствующий)
  • 6 – Необходимо встать на миграционный учет по действующим правилам (выдан ВНЖ)

Копирование и экспорт

Удобные форматы для обмена и интеграции.

1

Копирование JSON в Unicode-формате

Кнопка «Копировать» в шапке редактора преобразует текущий валидный JSON в строку с Unicode-экранированием (например, \u041F\u0440\u0438\u0432\u0435\u0442). Такой формат требуется для передачи данных в некоторые сервисы (например, в OpenSearch запросы).

После успешного копирования появляется уведомление.

Копирование доступно только для корректного JSON. При ошибках валидации покажется предупреждение.

2

Копирование описаний статусов

Кликните по любой информационной карточке (residenceRegistration или residenceAddress), чтобы скопировать расшифровку статуса или предупреждение об отсутствии адреса. Это удобно для добавления комментариев в задачи или отчёты.

Скопированный текст содержит полное пояснение статуса и, при необходимости, причину снятия.

Советы по эффективной работе

Рекомендации для администраторов и разработчиков.

1

Эффективная работа

  • Перед массовым изменением статусов используйте функцию копирования Unicode, чтобы сохранить исходный JSON.
  • Обращайте внимание на таймер обратного отсчёта – он помогает не выполнять действие раньше времени, когда причина снятия – отсутствие геоданных (статус 7, причина 2).
  • Если JSON не проходит валидацию, проверьте кавычки, лишние запятые или неэкранированные символы. Редактор покажет строку с ошибкой.
  • Используйте шаблоны из боковой панели для быстрого создания типовых блоков, затем изменяйте только нужные поля.

Внимание: Изменение статусов через кнопки немедленно обновляет JSON в редакторе. Перед применением убедитесь, что данные соответствуют реальному состоянию учёта.
